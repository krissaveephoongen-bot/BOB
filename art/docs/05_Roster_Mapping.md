# 05 · เทียบ Concept ใหม่กับเกมที่มีในโค้ด

> **ตัดสินใจแล้ว (12 พ.ย. 2026): ทางเลือก A** คงเกมจัดชั้นรถเข็น ใช้หน้าตาตัวละคร ศัตรู และฉากโรงเรียนตาม concept asset ที่ระบุโหมด "Action" ใน `02_Asset_List.md` ไม่ต้องผลิต

ตอนนี้โปรเจกต์มี 2 ชุดที่ไม่ตรงกัน:
- **Concept ใหม่** (`concept/*.png`): เกมแอ็กชันทำความสะอาดในโรงเรียน มี HP/ATK/DEF, combo attack, skill, บอส
- **โค้ดที่ทำไว้แล้ว** (`bob-game/`: prototype, Nakama server, `BobRules.cs`, analytics): เกมแข่ง "จัดชั้นรถเข็น" เลือกชิ้นส่วน 15 ชิ้นวางซ้อน 5 ชั้น มีปฏิกิริยาระหว่างชั้น แพ้/ชนะด้วยคะแนนตามสเปกศัตรู ไม่มี HP หรือการโจมตี

## 1. Hero — ตรงกันดีมาก

| Concept | id ในโค้ด | สีตรงกัน? | Ability ในโค้ด | เข้ากับบทบาทใน concept? |
| --- | --- | --- | --- | --- |
| กวาด (Sweeper) | `sweep` | ✓ ส้ม | จัดทัพ: สลับ 2 ชั้นติดกัน | พอได้ (ผู้นำ) |
| ฟอง (Foam) | `bubble` | ✓ ฟ้า | โล่ฟอง: กันปฏิกิริยาเสียที่แรงสุด | ✓ Support |
| ถู (Scrub) | `press` | ✓ เขียว | รีดเวลา: หยุดนาฬิกา 8 วิ | ✓ Control |
| สเปรย์ (Spray) | `spray` | ✓ ม่วง | เล็งเป้า: ดูคะแนนล่วงหน้า | ✓ Ranged/วิเคราะห์ |

→ **เสนอ: ใช้ชื่อ/หน้าตาตาม concept, คง id ในโค้ด** (`press` แสดงชื่อว่า "ถู") ไม่ต้องแก้ server/analytics

## 2. ศัตรู — ต่างกัน

| Concept | ใกล้เคียงในโค้ด | หมายเหตุ |
| --- | --- | --- |
| เจ้าคราบ (Dirt Monster) | `stain` (Stain คราบทั่วไป) | ✓ ใช้แทนกันได้ |
| สไลม์ (Slime) | `grease` (คราบมัน แพ้ความร้อน) | เปลี่ยนสีเหลือง→ม่วงได้ แต่ความหมาย "คราบมัน" หายไป |
| ขยะปีศาจ (Trash) | – | ใหม่ ต้องเพิ่มกฎ (เช่น แพ้ไม้กวาด+ถุงขยะ) |
| เชื้อโรค (Germ) | – | ใหม่ (เช่น แพ้น้ำยา/น้ำร้อน) |
| บอสคราบยักษ์ | – | ใหม่ |
| – | `dust`, `rust`, `scale` | ไม่มีใน concept ตัดหรือเก็บไว้เป็นศัตรูรอง |

## 3. ฉาก

Concept = โรงเรียน (ห้องเรียน, โรงอาหาร, สนามเด็กเล่น, ห้องใต้ดิน) · โค้ด = "ห้องเช่า" ห้องเดียว → เปลี่ยนเป็นโรงเรียนได้โดยไม่กระทบกฎเกม

## 4. ประเด็นหลัก: รูปแบบการเล่น

| ทางเลือก | ความหมาย | งานที่ตามมา |
| --- | --- | --- |
| **A. คงเกมจัดชั้นรถเข็น + ใช้หน้าตาจาก concept** (แนะนำ) | Hero/ฉาก/ศัตรูตาม concept, Hero ถือของมาวางรถเข็นแทนการตี; HUD ใช้ แถบเวลา/งบ แทน HP | ใช้ server, rules, analytics เดิมได้ทั้งหมด; ตัดอนิเมชัน Attack/Dodge และหน้า HP/ATK/DEF ออก (−20 animation) |
| B. เปลี่ยนเป็นเกมแอ็กชันตาม concept | วิ่งตีคราบ, combo, skill, อัปเกรด HP/ATK/DEF | ต้องออกแบบ GDD + server + rules ใหม่เกือบทั้งหมด งานอาร์ตเพิ่มขึ้นตามรายการ "Action" ใน `02_Asset_List.md` |
| C. ผสม: ต่อสู้เคลียร์คราบในห้อง แล้วจบด่านด้วยการจัดรถเข็นแข่ง | ได้ทั้งสองแบบ | งานมากที่สุด เสี่ยงขอบเขตบาน |

เอกสาร 00–04 เขียนให้รองรับทั้งสองทาง: ช่อง "โหมด" ใน Asset List บอกว่า asset ไหนใช้กับแบบไหน

## 5. ไฟล์ placeholder เดิม

ยังไม่ลบหรือแก้ไฟล์ใดใน `bob-art/unity/` หรือ `bob-art/source/` ทั้งหมดยังใช้ทดสอบได้ เมื่อเลือกทางแล้วจะปรับ `tools/make_art.py` ให้ placeholder ใช้ทรงหัว/สีตาม concept (ผ้าคาดหัวแดง, มวยคู่, ถัง, แว่น) เพื่อให้ทีมเห็นภาพใกล้ของจริงระหว่างรอ 3D
