# 15 · ศึกษาระบบ Task ของ Among Us → ข้อเสนอ "มินิเกมทำความสะอาด" ของ BOB

เวอร์ชัน 0.1 · 13 พ.ย. 2026 · สถานะ: **ขั้นศึกษา (ยังไม่แก้ GDD และโค้ด)** รอผู้ใช้ตัดสินใจตามข้อ 0

> เอกสารนี้ใช้ Among Us เป็นแรงบันดาลใจเชิง "กลไก" เท่านั้น **ห้ามคัดลอกภาพ เสียง UI โค้ด ชื่อ task หรือเลย์เอาต์ของ Among Us** มินิเกมทุกตัวข้างล่างออกแบบใหม่ในโลกของ BOB (โรงเรียน ฮีโร่ กวาด/ฟอง/ถู/สเปรย์ ศัตรูคราบ) และใช้ asset ของเราเอง

## 0. สรุปสั้นเพื่อตัดสินใจ

**ข้อเสนอ:** เปลี่ยนแกนรอบเล่นจาก "จัดรถเข็น 5 ชั้นแล้วส่งทดสอบ" เป็น **"ใบงาน = รายการ task ทำความสะอาด"** ทีมแยกย้ายไปทำมินิเกมสั้นๆ ตามจุดต่างๆ ในห้อง แถบความคืบหน้ารวมของทีมเต็ม 100% ก่อน = ชนะรอบ และเห็นแถบของทีมคู่แข่งเพื่อสร้างแรงกดดัน ดนตรีเพิ่มเลเยอร์ตามความคืบหน้า

ระบบรถเข็นซ้อนชั้น **ไม่ทิ้ง** แต่ย้ายมาเป็น task ประเภทหนึ่ง ("จัดรถเข็นตามสูตร") และเป็นตัว "เตรียมอุปกรณ์" ที่ทำให้มินิเกมอื่นง่ายขึ้น ข้อมูล ฮีโร่ ศัตรู ห้อง และ seed เดียวกันทุกทีม ใช้ต่อได้ทั้งหมด

| # | เรื่องที่ต้องตัดสินใจ | ข้อแนะนำ |
| --- | --- | --- |
| D1 | รถเข็นซ้อนชั้นอยู่ตรงไหน | **เป็น task ยาว 1 ตัวต่อรอบ + ให้บัฟ** (ข้อ 5.3) ไม่ใช่แกนหลักอีกต่อไป |
| D2 | แถบคู่แข่งอัปเดตแบบไหน | **ทีละขั้น 25%** (ข้อ 6.2) กดดันแต่ไม่ทำให้ทีมที่ตามหลังหมดกำลังใจ |
| D3 | ชนะรอบอย่างไร | **ใครถึง 100% ก่อนชนะ** หมดเวลาแล้วไม่มีใครครบ = เทียบ % (ข้อ 8) |
| D4 | ศัตรูทำอะไร | **ไม่ขโมยของ**: ศัตรูคือ "คราบที่โผล่ใหม่" เพิ่ม task ฉุกเฉินระหว่างรอบ (ข้อ 5.5) ไม่มีผู้ทรยศแบบ Among Us |
| D5 | ความยาวรอบ | **3 รอบ × 120 วิ** (แมตช์ ~7–8 นาทีรวมผลรอบ) แทน 100 วิเดิม |
| D6 | ชุดมินิเกมแรก (MVP) | **8 ตัว** ตามข้อ 4.2 ที่ทำซ้ำได้ด้วย component เดียวกัน |

## 1. ระบบ Task ของ Among Us (สรุปจากการค้นคว้า)

### 1.1 ประเภท task

| ประเภท | ความหมาย | หมายเหตุสำหรับเรา |
| --- | --- | --- |
| **Common** | ทุกคนในเกมได้ task ชุดเดียวกัน | ใช้ตรวจว่าใครทำจริง (ใน Among Us ใช้จับผู้ทรยศ) — เราใช้เป็น "งานรวม" ที่ทุกคนต้องช่วย |
| **Short** | ขั้นเดียว จบเร็ว | ส่วนใหญ่ของรายการ ให้จังหวะสั้นถี่ |
| **Long** | หลายขั้น หลายจุด หรือมีช่วงรอ | สร้างการเดินข้ามแผนที่และช่วงลุ้น |
| **Visual** | ทำเสร็จแล้วคนรอบข้างเห็นแอนิเมชันในโลก | เราใช้เป็นฟีดแบ็กที่ทั้งทีมเห็น ("ทุกคนเห็นห้องสะอาดขึ้น") |

- หัวห้องตั้งจำนวนได้ (สูงสุด common 2 · long 3 · short 5 ตามวิกิ) รายการเรียง common → long → short
- ประเภทของ task ขึ้นกับแผนที่ (task เดียวกันเป็น long ในแผนที่หนึ่ง และ short ในอีกแผนที่)
- task หลายขั้นมีลูกศรนำไปจุดถัดไป และ **นับเข้าแถบรวมเมื่อจบขั้นสุดท้ายเท่านั้น**
- ผีของลูกเรือที่ตายแล้วยังทำ task ได้และนับรวม (ไม่มีใครหลุดจากการช่วยทีม)

### 1.2 แถบความคืบหน้ารวม (Task bar)

- อยู่มุมบนซ้าย ทุกคนเห็น เติมเมื่อลูกเรือทำ task เสร็จ เต็ม = ลูกเรือชนะ
- ตั้งค่า "Task Bar Updates" ได้ 3 แบบ: **Always** (ทุกครั้งที่เสร็จ, ค่าเริ่มต้น) · **Meetings** (อัปเดตเฉพาะตอนประชุม) · **Never** (ซ่อน)
- การก่อกวน Comms ทำให้แถบมืดและซ่อนความคืบหน้า
- บทวิเคราะห์ชุมชนสรุปว่าการซ่อน/หน่วงแถบเพิ่มความไม่แน่นอนและความตึงเครียด แต่ลดข้อมูลที่ผู้เล่นใช้ตัดสินใจ

### 1.3 รูปแบบปฏิสัมพันธ์ของมินิเกม (สรุปเป็นหมวด ไม่ใช่ตัวเกม)

| หมวดกลไก | ตัวอย่างใน Among Us (ชื่อเพื่ออ้างอิงเท่านั้น) | ทักษะที่ใช้ | เวลาโดยประมาณ* |
| --- | --- | --- | --- |
| ลากด้วย "ความเร็วพอดี" | รูดบัตร | จังหวะมือ ลองใหม่ได้ | 2–6 วิ (ถ้าพลาดนานขึ้น) |
| จับคู่ลากเส้น | ต่อสายไฟ 4 สี | สังเกต + ลาก | 3–5 วิ ต่อจุด × 3 จุด |
| แตะตามลำดับ | ปลดล็อกตัวเลข 1–10 | ค้นหาด้วยตา | 4–8 วิ |
| จำลำดับ (Simon) | สตาร์ตเครื่อง | ความจำ | 15–25 วิ |
| กดค้าง / เติม | ทิ้งขยะ, เติมเชื้อเพลิง | ความอดทน + เดินหลายจุด | 3–5 วิ ต่อขั้น |
| เล็ง / แตะเป้าเคลื่อนที่ | ยิงอุกกาบาต | ความไว | 10–20 วิ |
| ลากของไปใส่ช่อง | เป่าใบไม้ออกจากตัวกรอง | ลากซ้ำ | 5–8 วิ |
| เลื่อนให้ตรงเส้น | ปรับกำลังเครื่องยนต์ | ความแม่น | 2–4 วิ |
| จังหวะ (กดตอนตรง) | ปรับสมดุลจานหมุน | timing | 4–8 วิ |
| **รอ + กลับมา** | ดาวน์โหลด/อัปโหลด, ตรวจตัวอย่าง (~60 วิ) | วางแผนเส้นทาง | รอ 8–60 วิ |
| ยืนให้ครบเวลา (visual) | สแกนร่างกาย | — | ~10 วิ |

\* ตัวเลขเวลาเป็นค่าประมาณจากคู่มือผู้เล่นและการเล่นทั่วไป วิกิที่ค้นมาไม่ได้ระบุเวลาเป็นทางการ ให้ใช้เป็นแนวทางเท่านั้น

### 1.4 ทำไม task ถึงสนุก (บทวิเคราะห์เพื่อนำมาใช้)

1. **เริ่มเล่นได้ทันที:** แต่ละมินิเกมสอนตัวเองในหน้าเดียว ไม่ต้องอ่านกฎ ใช้นิ้วเดียว
2. **สั้นและจับต้องได้:** 2–10 วิ ต่อชิ้น ได้ความรู้สึก "เสร็จ!" ถี่ๆ (micro-reward) ทุกชิ้นมีเสียงและภาพปิดงานชัด
3. **หลากหลายกลไก:** ลาก แตะ จำ รอ จังหวะ สลับกันจนไม่ซ้ำซาก แม้ทำซ้ำหลายสิบเกม
4. **แผนที่บังคับให้เดิน:** task กระจายหลายจุด + หลายขั้น ทำให้ต้องวางเส้นทาง เกิดการเจอกันและแบ่งงาน
5. **ความคืบหน้าร่วม:** แถบเดียวของทั้งทีม ทำให้งานเล็กของแต่ละคนมีความหมายต่อทีม
6. **ความกดดันจากเวลา/ภัย:** ใน Among Us มาจากผู้ทรยศ ใน BOB เราแทนด้วย **นาฬิกา + แถบของทีมคู่แข่ง + คราบโผล่ใหม่**
7. **ทำพลาดได้ ไม่ลงโทษหนัก:** พลาดแค่เสียเวลา ลองใหม่ทันที เหมาะกับเด็กและผู้เล่นทั่วไป

### 1.5 สิ่งที่ **ไม่** เอามา

- ผู้ทรยศ การฆ่า การโหวตไล่คน (ขัดกับ pillar co-op เป็นมิตรของ BOB และกฎ "ไม่มีข้อความตำหนิ")
- task ปลอม / การแกล้งทำ task
- ภาพ ชื่อ task เสียง และเลย์เอาต์ UI ทุกอย่างของ Among Us

| ไม่ใช้เลือดเย็น/ความรุนแรง | ศัตรูคราบโดน "ล้าง" ไม่ใช่ถูกฆ่า |

| ฮีโร่ | หมวดถนัด | โบนัสที่เสนอ |
| --- | --- | --- |
| กวาด | กวาด / เก็บขยะ | เส้นทางกวาดกว้างขึ้น 25% |

| สเปรย์ | ฉีด / เล็งจุด | เป้าใหญ่ขึ้น 20% และเห็นจุดซ่อนทั้งหมด |

## 3. โครงสร้างรอบใหม่ (ข้อเสนอ)

```
ใบงานห้อง (6 วิ) → 3-2-1 → ทำ task 120 วิ (แถบทีมเรา + แถบคู่แข่ง)
   → มีคนถึง 100% หรือหมดเวลา → ก่อน-หลัง (S25) → ผลรอบ → รอบถัดไป (3 รอบ)
```

- **ใบงาน (S20)** เปลี่ยนจาก "สเปก 4 ค่า" เป็น **รายการ task** ของห้อง + ไอคอนตำแหน่ง + ใครถนัดอะไร
- **seed เดียว:** ทุกทีมได้ห้อง รายการ task จุดวาง และเวลาโผล่ของคราบฉุกเฉินเหมือนกันทุกประการ (GDD 20) จึงเทียบความเร็วกันได้ยุติธรรม
- แต่ละทีมเล่นในห้องสำเนาของตัวเอง (เหมือน `bob_coop` ปัจจุบัน) ไม่เดินชนกับทีมคู่แข่ง

### 3.1 จำนวน task ต่อรอบ

| คนในทีม | Common (ทุกคนต้องช่วย) | Long | Short | รวมหน่วยงาน* |
| --- | --- | --- | --- | --- |
| 1 | 1 | 1 | 3 | ~10 |
| 2 | 1 | 2 | 4 | ~16 |
| 3 | 1 | 2 | 6 | ~20 |
| 4 | 1 | 3 | 7 | ~25 |

\* "หน่วยงาน" = น้ำหนักในแถบรวม: short = 1, long = 1 ต่อขั้น (2–3 ขั้น), common = 2 ต่อคน เป้าเวลาที่ทีมเฉลี่ยใช้ ≈ 90–100 วิ จาก 120 วิ ให้เหลือช่องให้พลาด ปรับจริงด้วย `server/balance-sim.js` แบบใหม่

- **task ไม่ผูกกับคน** (ต่างจาก Among Us): รายการเป็นของทีม ใครว่างก็หยิบไปทำได้ คนที่กำลังทำล็อก task นั้น (ไอคอนหน้าฮีโร่ขึ้นที่รายการ) เพื่อไม่ให้ทำซ้ำ — เหมาะกับ co-op มากกว่าและไม่มีใครค้าง
- **Common = งานรวม:** เช่น "ยกโต๊ะกลับที่" ต้องมีคน 2 คนกดค้างพร้อมกัน หรือทุกคนต้องทำส่วนของตัวเอง 1 ครั้ง (บังคับให้ร่วมมือ)

## 5. ระบบ Task list และแถบความคืบหน้า

### 5.1 รายการ task (HUD บนซ้าย แทน `HUD-OrderTicket`)

- แสดง 5 แถวแรก (ที่เหลือพับ "+3") แต่ละแถว: ไอคอนหมวด · ชื่อสั้น · ขั้น (เช่น 1/3) · หน้าฮีโร่ที่กำลังทำ · ✓
- แตะแถว = ลูกศรนำทางในฉาก + ไฮไลต์จุดงาน
- เรียง: ฉุกเฉิน (แดง) → common → long ที่กำลังรอ (มีนาฬิกา) → short

### 5.2 แถบความคืบหน้าทีม + คู่แข่ง (บนกลาง แทน `CHIP-Score`)

```
[⏱ 1:12]   ทีมเรา  ▓▓▓▓▓▓▓▓░░░░ 64%
           คู่แข่ง  ▓▓▓▓▓▓░░░░░░ 50%   (อัปเดตทุก 25%)
```

- ทีมเรา: อัปเดตทันทีที่จบ task (นับเมื่อจบขั้นสุดท้าย เหมือนต้นแบบ)
- คู่แข่ง: ข้อเสนอ 3 โหมด (ตั้งค่าในห้องส่วนตัวได้ ค่าเริ่มต้น = ขั้น 25%)

| โหมด | พฤติกรรม | ใช้เมื่อ |
| --- | --- | --- |
| **ขั้น 25% (ค่าเริ่มต้น)** | แถบคู่แข่งกระโดดเมื่อผ่าน 25/50/75% พร้อม toast "คู่แข่งถึง 75%!" | แรงกดดันเป็นจังหวะ ไม่จ้องแถบตลอด |
| ทันที | อัปเดตทุก task | โหมดแข่งจริงจัง |
| ซ่อนจน 30 วิ สุดท้าย | ไม่รู้จนท้ายรอบ แล้วเปิดพร้อมเสียงตีกลอง | Party / โหมดสนุก |

- **ไม่ให้ทีมที่ตามหลังหมดหวัง (anti-snowball):** ถ้าตามหลัง ≥ 25% ได้ "ลมเป่าช่วย" 1 ครั้ง (task short ตัวต่อไปเสร็จทันที) ทั้งสองทีมเห็นว่าใช้ (ตามกฎความโปร่งใสของ GDD 7)
- ข้อความเป็นบวกเท่านั้น ("ไล่ทันแล้ว!", "อีกนิดเดียว!") ไม่มีข้อความเยาะเย้ย

### 5.3 รถเข็นในระบบใหม่ (ข้อเสนอ D1)

- T04 "จัดรถเข็นตามสูตร" เป็น long task 1 ตัวต่อรอบ ใช้กติกาซ้อนชั้น/ปฏิกิริยาเดิมใน `BobRules`
- ผลค่า 4 ตัวของรถเข็นกลายเป็น **บัฟทั้งทีมในรอบนั้น**: ขจัดคราบ → T02/T16 เร็วขึ้น · ถนอม → พลาดไม่เสียน้ำยา · เร็ว → เดินเร็วขึ้น · เงา → ได้ดาวคุณภาพตอนจบ
- คนเข็นรถเข็นไปจุดงานได้ ถ้ารถเข็นอยู่ใกล้ (≤ 1.5 หน่วย) มินิเกมหมวดที่ตรงกับชิ้นส่วนบนรถเข็นได้ตัวช่วย — ทำให้การเข็นรถเข็นยังมีความหมาย

### 5.4 ระหว่างทำมินิเกม

- ตัวละครค้างที่จุด แสดงไอคอน "กำลังทำ" เหนือหัว เพื่อนเห็นว่าใครว่าง
- นาฬิกาและแถบยังแสดงบนขอบการ์ด (ไม่ซ่อน) เพื่อให้รู้สึกกดดันตลอด

### 5.5 ศัตรู = คราบโผล่ใหม่ (แทนศัตรูขโมยของ)

- seed กำหนด 2–3 จังหวะต่อรอบ (เช่น วิ 40, 75, 100) ศัตรูโผล่ที่จุดเดียวกันทั้งสองทีม
- ไม่จัดการใน 25 วิ → คราบลาม = เพิ่ม short 1 ตัว (แถบรวมถอยกลับนิดหน่อยเพราะตัวหารเพิ่ม)
- บอสคราบยักษ์ (รอบ 3) ต้องใช้ 2 คนทำ T16 พร้อมกัน

## 8. การชนะและคะแนน

- **ชนะรอบ:** ทีมแรกที่ถึง 100% → รอบจบทันทีทั้งสองทีม (ทีมที่ยังไม่ครบเห็นแถบของตัวเองค้างไว้ที่ %)
- หมดเวลาไม่มีใครครบ → % สูงกว่าชนะ; เสมอ → เวลาที่ถึง % นั้นก่อน
- **ดาวคุณภาพ (ไม่ใช่เงื่อนไขชนะ):** พลาดน้อย, จัดการฉุกเฉินทัน, ค่าเงาจากรถเข็น → ใช้ให้รางวัลและแรงจูงใจเล่นให้ดี ไม่ใช่แค่เร็ว
- แมตช์ = ชนะ 2 ใน 3 รอบ (เหมือนเดิม) รางวัลเท่ากันทุกคนในทีม (GDD เดิม)

## 9. สิ่งที่กติกาและ server ต้องเปลี่ยน (ยังไม่ทำ)

### 9.1 กติกา (`prototype/index.html` → `server/modules/index.js` → `BobRules.cs`)

| ตัดสินผล | `bob_score_stack` ให้คะแนนกองรถเข็น | `TaskProgress(team)` = Σ weight ที่เสร็จ / Σ weight ทั้งหมด; `bob_score_stack` ยังใช้กับ T04 เพื่อคำนวณบัฟ |

### 9.2 Server แบบ authoritative (`server/match.js`)

- **opcode ใหม่ (client → server):** `16 TASK_BEGIN {task, step}` · `17 TASK_DONE {task, step, ms, sample}` · `18 TASK_CANCEL {task}`
- **opcode ใหม่ (server → client):** `19 PROGRESS {team: %, rival: % (ตามโหมด), done: [ids]}` · `20 EMERGENCY {id, spot, at}` · `21 TASK_LOCK {task, by}`
- **ตรวจกันโกง** (มินิเกมเล่นฝั่ง client จึงต้องตรวจความเป็นไปได้):
  - ผู้เล่นต้องอยู่ใกล้จุดงาน (`mpDist ≤ NEAR`) ตลอดตั้งแต่ BEGIN ถึง DONE (server รู้ตำแหน่งอยู่แล้วจาก MOVE)
  - `DONE` ต้องมาไม่เร็วกว่า `TaskMinMs[id]` (เช่น T02 ≥ 1.8 วิ) นับจาก BEGIN ตามนาฬิกา server
  - task รอ (T09) server นับเวลาเอง client ส่ง DONE ขั้น 2 ก่อนครบ = ปฏิเสธ
  - ขั้นต้องเรียงตามลำดับ และ task ที่ล็อกโดยคนอื่นทำไม่ได้
  - `sample` = สรุปท่าทางสั้นๆ (เช่น ระยะลากรวม, จำนวนแตะ) เก็บใน analytics เพื่อจับบอทภายหลัง (ไม่ใช่เงื่อนไขผ่าน)
- `bob_coop` คงโครงเดิม (สองทีม ห้องสำเนา seed เดียว) — เปลี่ยนแค่สถานะรอบและผลรอบ

### 9.3 Analytics ใหม่ (`server/analytics.js`)

`task_done {task, step, ms, char, round}` · `task_abandon` · `emergency_missed` · `round_progress {team_pct, rival_pct, at_sec}` — ใช้ปรับเวลาเป้าของแต่ละมินิเกมใน dashboard

### 9.4 Unity

| เล่นซ้ำแล้วเบื่อ | retention ตก | ความยากเพิ่มตามด่าน, สุ่มชุด task จาก seed, ฉุกเฉินจากศัตรู, รถเข็นให้บัฟต่างกัน |
| ผู้เล่นแยกย้ายกันจนไม่รู้สึก co-op | เสีย pillar ร่วมมือ | common task ที่ต้องทำพร้อมกัน (T13), รถเข็นให้บัฟคนใกล้, ping เดิม |
| มินิเกมฝั่ง client โกงได้ | ทีมโกงชนะ | ตรวจระยะ + เวลาขั้นต่ำ + ลำดับขั้นบน server (ข้อ 9.2) |
| แถบคู่แข่งทำให้ทีมที่แพ้ท้อ | เลิกเล่นกลางแมตช์ | โหมดขั้น 25%, ลมเป่าช่วย, ข้อความบวก |
| ดูคล้าย Among Us เกินไป | ปัญหาลิขสิทธิ์/ภาพลักษณ์ | ไม่มีผู้ทรยศ ไม่ใช้ชื่อ/ภาพ/เสียง/เลย์เอาต์ของเขา ธีมเป็นงานบ้านโรงเรียนของเราเอง |

**คำถามที่ยังเปิด:** โหมด Community (10–15 คน) จะเป็น task list ขนาดใหญ่ของทั้งอาคารหรือไม่ · Solo จะแข่งกับ "ผลงานบันทึก" (ghost progress) ของผู้เล่นอื่นได้เลยหรือไม่ (แนะนำ: ได้ เพราะ seed เดียวกัน)
