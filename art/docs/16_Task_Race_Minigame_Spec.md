## 1. ภาพรวมรอบเล่น

```
ใบงานห้อง (S20, 6 วิ) → 3-2-1 → Task race 120 วิ
   ├─ ทีมแยกย้ายไปทำมินิเกมที่จุดงาน (ทีละคนต่อ task)
   ├─ แถบทีมเรา + แถบคู่แข่งบน HUD ("ทีมฟ้า 4/6 · 67%")
   ├─ คราบฉุกเฉินโผล่ตามเวลาจาก seed (เหมือนกันทั้งสองทีม)
   └─ ดนตรีเพิ่มเลเยอร์ตามความคืบหน้าและความใกล้ชนะของคู่แข่ง
→ มีทีมถึง 100% หรือหมดเวลา → ห้องสะอาด (S25, 4 วิ) → ผลรอบ (S26) → รอบถัดไป
```

- ทั้งสองทีมได้ **seed เดียวกัน**: ห้อง รายการ task จุดงานที่เปิด ความยาก และเวลาโผล่ของคราบฉุกเฉินเหมือนกันทุกประการ แต่ละทีมเล่นในห้องสำเนาของตัวเอง (โครง `bob_coop` เดิม)
- ไม่มีการกระทำใดที่ไปรบกวนทีมคู่แข่งได้ การแข่งคือ "ใครทำความสะอาดเสร็จก่อน" เท่านั้น
- แมตช์ = ชนะ 2 ใน 3 รอบ รางวัลเท่ากันทุกคนในทีม (GDD 5, 6)

## 2. ใบงาน = รายการ task ของทีม

### 2.1 ประเภท task

| ประเภท | ความหมาย | น้ำหนักในแถบ | ไอคอนที่รายการ |
| --- | --- | --- | --- |
| **Short** | ขั้นเดียว 3–10 วิ ที่จุดเดียว | 1 | วงกลมหมวด |
| **Long** | 2–3 ขั้น ต่างจุด หรือมีช่วงรอ | 1 ต่อขั้น | วงกลมหมวด + ตัวเลขขั้น "1/3" |
| **Common** | งานรวมที่ต้องใช้หลายคน (พร้อมกันหรือทุกคนคนละส่วน) | 2 ต่อคนที่ต้องร่วม | ไอคอนมือสองข้าง |
| **Emergency** | คราบฉุกเฉินที่โผล่กลางรอบ (ข้อ 4) | 1 | ขอบแดง + นาฬิกา 25 วิ |

- **นับเข้าแถบเมื่อจบขั้น** (long ได้ทีละ 1 ต่อขั้นที่เสร็จ) ทำให้แถบขยับถี่ ไม่ต้องรอจบทั้ง task
- **task ไม่ผูกกับคน:** รายการเป็นของทีม ใครว่างก็หยิบไปทำได้ คนที่เปิดมินิเกมจะ **ล็อก** task นั้น (หน้าฮีโร่ขึ้นที่แถวรายการ) จนกว่าจะจบหรือปิด กันทำซ้ำ
- ปิดมินิเกมกลางคัน: ความคืบหน้าของขั้นนั้นเก็บไว้ **10 วิ** และล็อกปลดทันที คนอื่นมาทำต่อได้

### 2.2 จำนวน task ต่อรอบ (ตามขนาดทีม)

| คนในทีม | Common | Long | Short | น้ำหนักรวม (ประมาณ) | ตัวอย่างข้อความบน HUD |
| --- | --- | --- | --- | --- | --- |
| 1 | 0 (T13 ใช้รถเข็นดันแทน = นับเป็น short) | 2 (T04 + 1) | 4 | ~10 | "ทีมฟ้า 3/6" |
| 2 | 1 | 2 | 4 | ~14 | "ทีมฟ้า 4/7" |
| 3 | 1 | 2 | 6 | ~19 | "ทีมฟ้า 5/9" |
| 4 | 1 | 3 | 7 | ~25 | "ทีมฟ้า 6/11" |

- ตัวเลข "4/6" บน HUD = **จำนวน task ที่เสร็จ / ทั้งหมด** (คนเข้าใจทันที) ส่วนแถบและ % ใช้ **น้ำหนัก** (ยุติธรรมกับ long) ทั้งสองแสดงคู่กัน
- T04 (รถเข็น) อยู่ในทุกรอบเสมอ ส่วนตัวอื่น seed สุ่มจากชุดที่เปิดในบทนั้น (ข้อ 5.3) โดยต้องมีหมวดถนัดของฮีโร่ทุกตัวในทีมอย่างน้อย 1 ตัว
- เป้าเวลา: ทีมเฉลี่ยครบ 100% ที่ **90–100 วิ** จาก 120 วิ เหลือที่ให้พลาดและคราบฉุกเฉิน ปรับด้วย `server/balance-sim.js` ฉบับ task (ยังไม่ทำ)

### 2.3 สูตรความคืบหน้า

```
Progress(team) = Σ น้ำหนักขั้นที่เสร็จ / Σ น้ำหนักทั้งหมดในรายการ (รวม task ฉุกเฉินที่ลามแล้ว)
```

- คราบฉุกเฉินที่ปล่อยจนลาม = เพิ่ม short 1 ตัวเข้ารายการ ตัวหารเพิ่ม แถบจึงถอยเล็กน้อย (เช่น 10/14 = 71% → 10/15 = 67%) แสดงด้วยแอนิเมชันถอยช้าๆ สีส้ม ไม่ใช่สีแดง
- ถึง 100% = จบรอบทันทีทั้งสองทีม

### 2.4 แถบคู่แข่ง

| โหมด | พฤติกรรม | ค่าเริ่มต้น |
| --- | --- | --- |
| ขั้น 25% | แถบคู่แข่งกระโดดเมื่อผ่าน 25/50/75% พร้อม toast "ทีมแดงถึง 75%!" และ stinger | ✓ ทุกโหมดจับคู่ |
| ทันที | อัปเดตทุกขั้นที่คู่แข่งทำเสร็จ | ห้องส่วนตัว |
| ซ่อนจน 30 วิสุดท้าย | ไม่รู้จนเหลือ 30 วิ แล้วเปิดพร้อมเสียงตีกลอง | ห้องส่วนตัว / Party |

- เมื่อคู่แข่งถึง **≥ 85%** แถบคู่แข่งอัปเดตแบบทันทีเสมอทุกโหมด (ให้รู้ว่าใกล้แพ้จริง และใช้ขับดนตรี L4)
- **ลมเป่าช่วย (anti-snowball):** ทีมที่ตามหลัง ≥ 25% (ตามค่าที่เห็นบนจอ) ได้ปุ่ม "ลมเป่าช่วย" 1 ครั้งต่อรอบ กดแล้ว short ตัวถัดไปที่เปิดเสร็จทันที ทั้งสองทีมเห็นว่าใช้ (GDD 17 กฎ 7)
- ข้อความทุกข้อความเป็นบวก ("ไล่ทันแล้ว!", "อีกนิดเดียว!") ไม่มีข้อความเยาะหรือชี้ว่าใครช้า

### 2.5 การชนะรอบ

1. ทีมแรกที่ถึง 100% ชนะรอบ ทั้งสองทีมหยุดทันที
2. หมดเวลาไม่มีใครครบ → % (ตามน้ำหนัก) สูงกว่าชนะ
3. % เท่ากัน → ทีมที่ถึง % นั้นก่อน (เวลาบน server) ชนะ
4. ยังเท่า (แทบเป็นไปไม่ได้) → เสมอ ทั้งสองทีมได้รางวัลเท่าทีมชนะ (กฎเดิม GDD 5)

**ดาวคุณภาพทีม (ไม่ใช่เงื่อนไขชนะ):** ★ จัดการฉุกเฉินทันทุกตัว · ★ ไม่มี task ที่ถูกปิดกลางคันแล้วหมดเวลาเก็บ · ★ รถเข็น T04 ผ่านสูตร (ค่าเงา) → ใช้ในรางวัลและภารกิจ ไม่มีสถิติรายคน

## 4. คราบฉุกเฉิน (ศัตรู)

- ศัตรู **ไม่ขโมยของ ไม่ไล่ตาม ไม่ทำร้าย** ศัตรูคือคราบที่มีชีวิตซึ่งโผล่ขึ้นมาเป็น task ฉุกเฉิน

## 7. การเข้าถึงและความยุติธรรม

- **โหมดช่วยกดค้าง** (ตั้งค่า): gesture ลาก (T01 T02 T05 T08 T14) เปลี่ยนเป็นกดค้างที่เป้าแล้วแถบเติมเอง ช้ากว่าปกติ 30% แต่เล่นได้ด้วยนิ้วที่ไม่คล่อง ไม่ส่งผลต่อการจับคู่
- **ตาบอดสี:** ถัง ปุ่ม และเป้าทุกตัวมีรูปร่าง/ไอคอนต่างกัน
- **เสียงปิด:** ทุกสัญญาณ (ฉุกเฉิน, คู่แข่งผ่านขั้น, รอครบ) มีภาพและการสั่นคู่
- **ความต่างของเครื่อง:** เกณฑ์ใช้ระยะใน u (ไม่ใช่พิกเซล) และไม่มีมินิเกมที่ต้องเร็วกว่า 0.4 วิ ต่อการกระทำ
- **ไม่มีสถิติรายคน:** server เก็บเวลาต่อมินิเกมเพื่อปรับสมดุลเท่านั้น ผู้เล่นไม่เห็นว่าใครช้า (GDD 18)

## 8. สัญญากับ server (ยังไม่ทำ อ้างอิงจากเอกสาร 15 ข้อ 9)

| ทิศทาง | opcode | ข้อมูล | ตรวจ |
| --- | --- | --- | --- |
| client → server | `16 TASK_BEGIN` | `{task, step}` | อยู่ใกล้จุด (`≤ NEAR`), task ไม่ถูกล็อก, ขั้นถัดไปถูกลำดับ |
| client → server | `17 TASK_DONE` | `{task, step, ms, sample}` | อยู่ใกล้จุดตลอด, `ms ≥ TaskMinMs[id]` ตามนาฬิกา server, T09 รอครบ, T13 สองคนซ้อนกัน |
| client → server | `18 TASK_CANCEL` | `{task}` | ปลดล็อก เก็บความคืบหน้า 10 วิ |
| server → client | `19 PROGRESS` | `{team: {done, total, pct}, rival: {pct ตามโหมด}, done: [ids]}` | ส่งเมื่อมีขั้นเสร็จและเมื่อคู่แข่งข้ามขั้น |
| server → client | `20 EMERGENCY` | `{id, enemy, spot, at, graceSec}` | ส่งพร้อมกันทั้งสองทีม |
| server → client | `21 TASK_LOCK` | `{task, by}` | แจ้งทั้งทีม |

ค่าคงที่ใหม่: `TaskRoundTime = 120`, `TaskMinMs[id]` (ตามตารางข้อ 5), `EmergencyGraceSec = 25`, `RivalStepPct = 25`, `RivalLiveFromPct = 85`, `AssistTrailPct = 25`, `TaskResumeSec = 10`
ต้องคงหลักเดิม: กฎมีที่เดียวที่ `prototype/index.html` → `server/build-module.js` สร้าง `modules/index.js` → `BobTasks.cs` (pure C#) แก้ตามด้วยมือ และ `unity-check` เทียบผล

Analytics ใหม่: `task_done {task, step, ms, char, round, d}` · `task_abandon` · `emergency_missed` · `round_progress {team_pct, rival_pct, at_sec}` · `assist_used`
