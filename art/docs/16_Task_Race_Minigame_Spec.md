## 1. ภาพรวมรอบเล่น

```
ใบงานห้อง (S20, 6 วิ) → 3-2-1 → Task race 120 วิ
   ├─ ทีมแยกย้ายไปทำมินิเกมที่จุดงาน (ทีละคนต่อ task)
   ├─ แถบทีมเรา + แถบคู่แข่งบน HUD ("ทีมฟ้า 4/6 · 67%")
   ├─ คราบฉุกเฉินโผล่ตามเวลาจาก seed (เหมือนกันทั้งสองทีม)
   └─ ดนตรีเพิ่มเลเยอร์ตามความคืบหน้าและความใกล้ชนะของคู่แข่ง
→ มีทีมถึง 100% หรือหมดเวลา → ห้องสะอาด (S25, 4 วิ) → ผลรอบ (S26) → รอบถัดไป
```

- ทั้งสองทีมได้ **seed เดียวกัน**: ห้อง รายการ task จุดงานที่เปิด ความยาก และเวลาโผล่ของคราบฉุกเฉินเหมือนกันทุกประการ แต่ละทีมเล่นในห้องสำเนาของตัวเอง (โครง `bob_coop` เดิม)
- ไม่มีการกระทำใดที่ไปรบกวนทีมคู่แข่งได้ การแข่งคือ "ใครทำความสะอาดเสร็จก่อน" เท่านั้น
- แมตช์ = ชนะ 2 ใน 3 รอบ รางวัลเท่ากันทุกคนในทีม (GDD 5, 6)

## 2. ใบงาน = รายการ task ของทีม

### 2.1 ประเภท task

| ประเภท | ความหมาย | น้ำหนักในแถบ | ไอคอนที่รายการ |
| --- | --- | --- | --- |
| **Short** | ขั้นเดียว 3–10 วิ ที่จุดเดียว | 1 | วงกลมหมวด |
| **Long** | 2–3 ขั้น ต่างจุด หรือมีช่วงรอ | 1 ต่อขั้น | วงกลมหมวด + ตัวเลขขั้น "1/3" |
| **Common** | งานรวมที่ต้องใช้หลายคน (พร้อมกันหรือทุกคนคนละส่วน) | 2 ต่อคนที่ต้องร่วม | ไอคอนมือสองข้าง |
| **Emergency** | คราบฉุกเฉินที่โผล่กลางรอบ (ข้อ 4) | 1 | ขอบแดง + นาฬิกา 25 วิ |

- **นับเข้าแถบเมื่อจบขั้น** (long ได้ทีละ 1 ต่อขั้นที่เสร็จ) ทำให้แถบขยับถี่ ไม่ต้องรอจบทั้ง task
- **task ไม่ผูกกับคน:** รายการเป็นของทีม ใครว่างก็หยิบไปทำได้ คนที่เปิดมินิเกมจะ **ล็อก** task นั้น (หน้าฮีโร่ขึ้นที่แถวรายการ) จนกว่าจะจบหรือปิด กันทำซ้ำ
- ปิดมินิเกมกลางคัน: ความคืบหน้าของขั้นนั้นเก็บไว้ **10 วิ** และล็อกปลดทันที คนอื่นมาทำต่อได้

### 2.2 จำนวน task ต่อรอบ (ตามขนาดทีม)

| คนในทีม | Common | Long | Short | น้ำหนักรวม (ประมาณ) | ตัวอย่างข้อความบน HUD |
| --- | --- | --- | --- | --- | --- |
| 1 | 0 (T13 ใช้รถเข็นดันแทน = นับเป็น short) | 2 (T04 + 1) | 4 | ~10 | "ทีมฟ้า 3/6" |
| 2 | 1 | 2 | 4 | ~14 | "ทีมฟ้า 4/7" |
| 3 | 1 | 2 | 6 | ~19 | "ทีมฟ้า 5/9" |
| 4 | 1 | 3 | 7 | ~25 | "ทีมฟ้า 6/11" |

- ตัวเลข "4/6" บน HUD = **จำนวน task ที่เสร็จ / ทั้งหมด** (คนเข้าใจทันที) ส่วนแถบและ % ใช้ **น้ำหนัก** (ยุติธรรมกับ long) ทั้งสองแสดงคู่กัน
- **ต้นแบบแผนที่ (14 พ.ย. 2026)** ลงกลไกนี้แล้วใน `TaskRaceRound` (doc 24 ข้อ 14): สุ่มรายการจาก seed เดียวกันทั้งสองทีม, T04 มาก่อนเสมอ, 6 / 7 / 9 ตัวตามขนาดทีม, สถานีเติมงานใหม่เมื่อทำเสร็จจึงใช้ 3–6 สถานีต่อเกาะได้; ที่ D2/D3 ทีม 3–4 คนลด short ลงขั้นละ 1 ตัว เพื่อไม่ให้เกินเป้า 90–100 วิ หลังตัวคูณเวลา 15%/ขั้น — HUD `BobTaskRaceHud` (doc 24 ข้อ 10) วาดตัวเลข "N/M" และแถบน้ำหนักตามข้อนี้แล้ว
- T04 (รถเข็น) อยู่ในทุกรอบเสมอ ส่วนตัวอื่น seed สุ่มจากชุดที่เปิดในบทนั้น (ข้อ 5.3) โดยต้องมีหมวดถนัดของฮีโร่ทุกตัวในทีมอย่างน้อย 1 ตัว
- เป้าเวลา: ทีมเฉลี่ยครบ 100% ที่ **90–100 วิ** จาก 120 วิ เหลือที่ให้พลาดและคราบฉุกเฉิน ปรับด้วย `server/balance-sim.js` ฉบับ task (ยังไม่ทำ)

### 2.3 สูตรความคืบหน้า

```
Progress(team) = Σ น้ำหนักขั้นที่เสร็จ / Σ น้ำหนักทั้งหมดในรายการ (รวม task ฉุกเฉินที่ลามแล้ว)
```

- คราบฉุกเฉินที่ปล่อยจนลาม = เพิ่ม short 1 ตัวเข้ารายการ ตัวหารเพิ่ม แถบจึงถอยเล็กน้อย (เช่น 10/14 = 71% → 10/15 = 67%) แสดงด้วยแอนิเมชันถอยช้าๆ สีส้ม ไม่ใช่สีแดง
- ถึง 100% = จบรอบทันทีทั้งสองทีม

### 2.4 แถบคู่แข่ง

| โหมด | พฤติกรรม | ค่าเริ่มต้น |
| --- | --- | --- |
| ขั้น 25% | แถบคู่แข่งกระโดดเมื่อผ่าน 25/50/75% พร้อม toast "ทีมแดงถึง 75%!" และ stinger | ✓ ทุกโหมดจับคู่ |
| ทันที | อัปเดตทุกขั้นที่คู่แข่งทำเสร็จ | ห้องส่วนตัว |
| ซ่อนจน 30 วิสุดท้าย | ไม่รู้จนเหลือ 30 วิ แล้วเปิดพร้อมเสียงตีกลอง | ห้องส่วนตัว / Party |

- เมื่อคู่แข่งถึง **≥ 85%** แถบคู่แข่งอัปเดตแบบทันทีเสมอทุกโหมด (ให้รู้ว่าใกล้แพ้จริง และใช้ขับดนตรี L4)
- **ลมเป่าช่วย (anti-snowball):** ทีมที่ตามหลัง ≥ 25% (ตามค่าที่เห็นบนจอ) ได้ปุ่ม "ลมเป่าช่วย" 1 ครั้งต่อรอบ กดแล้ว short ตัวถัดไปที่เปิดเสร็จทันที ทั้งสองทีมเห็นว่าใช้ (GDD 17 กฎ 7)
- ข้อความทุกข้อความเป็นบวก ("ไล่ทันแล้ว!", "อีกนิดเดียว!") ไม่มีข้อความเยาะหรือชี้ว่าใครช้า

### 2.5 การชนะรอบ

1. ทีมแรกที่ถึง 100% ชนะรอบ ทั้งสองทีมหยุดทันที
2. หมดเวลาไม่มีใครครบ → % (ตามน้ำหนัก) สูงกว่าชนะ
3. % เท่ากัน → ทีมที่ถึง % นั้นก่อน (เวลาบน server) ชนะ
4. ยังเท่า (แทบเป็นไปไม่ได้) → เสมอ ทั้งสองทีมได้รางวัลเท่าทีมชนะ (กฎเดิม GDD 5)

**ดาวคุณภาพทีม (ไม่ใช่เงื่อนไขชนะ):** ★ จัดการฉุกเฉินทันทุกตัว · ★ ไม่มี task ที่ถูกปิดกลางคันแล้วหมดเวลาเก็บ · ★ รถเข็น T04 ผ่านสูตร (ค่าเงา) → ใช้ในรางวัลและภารกิจ ไม่มีสถิติรายคน

> **สถานะ 16 พ.ย. 2026:** ดาวดวงแรก (ฉุกเฉินทันทุกตัว) นับจริงแล้ว — `StorySeries.NoteEmergency(cleared)` ถูกเรียกจาก `BobEmergencyStains` ตอนปราบ/ตอนลาม และการ์ดจบบทแสดงบรรทัดที่ 4 `คราบ n/m` (✓ เมื่อครบทุกตัว).
>
> **อัปเดต 16 พ.ย. 2026 (อีกสองดวงนับแล้ว):** ดวงที่ 2 **"ไม่ทิ้งงาน"** — `BobTaskRaceHud.HideCard` เรียก `StorySeries.NoteCardClosed()` เมื่อปิดการ์ดทั้งที่สถานียังสกปรก (ปุ่ม ×, จอย, หรือรอบจบ) และจำ `TaskId` ไว้; พอใบงานนั้นกลายเป็น `Done` ในรอบเดียวกัน `RenderRows → NoteRecoveredJobs` เรียก `NoteCardRecovered()` คืนให้ (ปิดกลางคันไม่ใช่ความผิดจนกว่านาฬิกาจะหมด). ดวงที่ 3 **"รถเข็นผ่านสูตร"** — `NoteCart(passed)` ถูกเรียกครั้งเดียวต่อการล็อกสูตรของแต่ละรอบ (ดักที่การเปลี่ยน `round.CartPassed` จาก null) และดวงนี้ต้อง **ผ่านทุกครั้งที่ล็อก**; บทที่ไม่เคยล็อกสูตรเลย = ไม่มีดาว (กฎเดียวกับคราบ). ทั้งสามดวงเป็น **รายงาน** ไม่ใช่เงื่อนไขชนะ: บทที่ชนะ 2 รอบยังได้ 2 ดาวเท่าเดิม (`unity-check` มี assertion ยืนยัน) และบรรทัดคุณภาพบนการ์ดจบบทจะโผล่เฉพาะดวงที่ "มีเรื่องให้รายงาน" — `· คราบ n/m` · `· ไม่ทิ้งงาน` · `· รถเข็น p/r`

### 2.6 คะแนนรวมของแมตช์ (ตัวที่ขึ้นลีดเดอร์บอร์ด)

หนึ่งแมตช์จบ = หนึ่งคะแนน สูตรเดียวอยู่ในสามที่ (`BobRaceScore.Of` ฝั่งเครื่อง, `taskRaceScore` ใน `prototype/index.html`
และ `server/modules/index.js`) และมีตารางเลขชุดเดียวกันคุมทั้งสองฝั่ง (`unity-check` + `server/task-race-test.js`):

| องค์ประกอบ | น้ำหนัก | เหตุผล |
| --- | --- | --- |
| งานที่ทำเสร็จ | × 100 | งานคือหัวใจของรอบ (บทที่จบทั้งบทใช้ยอดรวมของซีรีส์) |
| เงื่อนไขรถเข็นที่ผ่าน | × 75 (สูงสุด 4; บท = จำนวนครั้งที่ล็อกผ่าน 0–3) | รางวัลของคนที่เล่น T04 ครบ |
| วินาทีที่เหลือ | × 2 (สูงสุด 120) | เร็วได้เปรียบ แต่ไม่ท่วมทุกอย่าง |
| ชนะ / เสมอ | +400 / +150 | ผลการแข่งยังสำคัญที่สุด |
| ความยาก | × 1.00 / 1.20 / 1.40 (D1–D3) | เล่นยากได้มากกว่า เลขจำนวนเต็ม หารปัดลงทั้งสองภาษา |

ตัวอย่าง: 8 งาน + รถเข็น 4 + เหลือ 60 วิ + ชนะ ที่ D1 = 1,620 คะแนน · เล่นชุดเดียวกันที่ D3 = 2,268

การส่งขึ้นบอร์ด: `TaskRaceModeManager.EndMatch` คำนวณ `LastScore` แล้ว `BobRaceScoreReporter` (UGS) ส่งเข้า
`global_high_score` **ครั้งเดียวต่อแมตช์** และเฉพาะเมื่อเครื่องล็อกอินแล้ว — ออฟไลน์เล่นได้ปกติแต่ไม่มีการส่ง
(หน้าผลแสดง "คะแนน N" คู่กับสถิติเดิมเสมอ). ผลตรวจ `record:false` (ภาพ verify) ไม่ส่งอะไรขึ้นบอร์ด

## 3. กติกากลางของมินิเกม
| หัวข้อ | กติกา |
| --- | --- |
| เริ่ม | ยืนที่จุดงาน (`TaskSpot`, ระยะ ≤ 1.2 หน่วย) → ปุ่มหลักตามบริบทเปลี่ยนเป็น "ทำงาน: <ชื่อ>" → แตะ |
| การแสดง | การ์ด overlay กลางจอ **1400 × 860u** (`MINI-Host`, S28) ฉากยังเห็นที่ขอบ นาฬิกาและแถบทีม/คู่แข่งย่อไว้บนขอบการ์ด |
| การควบคุม | **นิ้วเดียว** ในการ์ด ใช้ gesture 5 แบบ: ลากถู (scrub), ลากตามเส้น (trace), แตะ/แตะค้าง (tap/hold), ลากวาง (drag & drop), จังหวะ (timing) |
| ความยาว | ทุกขั้น 2–12 วิ ไม่มีขั้นไหนเกิน 12 วิ |
| สอนในตัว | ครั้งแรกของแต่ละมินิเกมมี `ui_hand_hint` ทำท่า 1 รอบ ไม่มีข้อความยาว (≤ 6 คำ) |
| พลาด | พลาด = เสียเวลาเท่านั้น ไม่มีโทษลบแถบ ไม่มีข้อความตำหนิ |
| ปิด | ปุ่ม × บนขวา 144u หรือโยกจอยออก ความคืบหน้าขั้นเก็บ 10 วิ |
| ระหว่างทำ | ตัวละครค้างที่จุด มีไอคอน "กำลังทำ" เหนือหัว เพื่อนเห็นว่าใครว่าง |
| ปิดงาน | `sting_task_done` (ตามคีย์เพลง) + ประกาย + จุดในห้องเปลี่ยนจากสกปรกเป็นสะอาด (`_DirtAmount` → 0) **ทั้งทีมเห็น** + สั่น medium |
