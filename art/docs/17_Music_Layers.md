# 17 · ดนตรีเลเยอร์ของ Task Race

เวอร์ชัน 1.0 · 13 พ.ย. 2026 · สถานะ: แผนพร้อมทำ ยังไม่มีไฟล์เพลงและโค้ด
ใช้คู่กับ `16_Task_Race_Minigame_Spec.md` (สถานะรอบ), `12_Sound_Manifest.md` ข้อ 5–6 (ไฟล์เสียงและ licence), `11_UX_UI_Spec.md` ข้อ 11 (เสียงต่อเหตุการณ์) และ GDD หัวข้อ 22

**สรุป:** ในรอบ task race ใช้ **เพลงเดียวแยก 4 stem** ที่เล่นพร้อมกันตลอด เปิด/ปิดแต่ละ stem ตามความคืบหน้าของทีมเรา ความใกล้ชนะของคู่แข่ง และเวลาที่เหลือ ทุกการเปลี่ยนรอจังหวะห้องเพลงถัดไป จึงไม่สะดุด ผู้เล่นรู้สึกว่า "เพลงเร่ง" เมื่อใกล้จบหรือเมื่อคู่แข่งใกล้ชนะ โดยไม่ต้องมองแถบ

## 1. สเปกเพลง

| หัวข้อ | ค่า |
| --- | --- |
| ความยาว loop | 8 ห้อง 4/4 ที่ 120 bpm = **16.0 วิ** (ทุก stem ยาวเท่ากันทุกตัวอย่างพอดี) |
| คีย์ | C major (stinger ทุกตัวอยู่ในคีย์เดียวกัน ให้ซ้อนกับเพลงได้) |
| โทน | สดใสแบบของเล่น งานบ้านมหากาพย์แบบเบาๆ (GDD 14) ไม่มีเสียงร้อง |
| รูปแบบไฟล์ | WAV 48 kHz stereo ตอนผลิต → นำเข้า Unity เป็น Vorbis Q60, Streaming |
| ระดับ | แต่ละ stem master ที่ −18 LUFS เมื่อเล่นเดี่ยว รวม 4 stem ไม่เกิน −14 LUFS, peak ≤ −1 dBTP |

## 2. เลเยอร์

| เลเยอร์ | ไฟล์ | เครื่องดนตรี | เปิดเมื่อ | ปิดเมื่อ |
| --- | --- | --- | --- | --- |
| L1 พื้น | `mus_task_L1` | เบส + กลองเบา (kick/clap) | ตลอดรอบ (เริ่มที่ "ลุย!") | จบรอบ |
| L2 ทำนอง | `mus_task_L2` | marimba / ไซโลโฟน ธีมทำความสะอาด | ทีมเรา ≥ 25% | ทีมเรา < 15% (ถอยเพราะคราบลาม) |
| L3 เร่ง | `mus_task_L3` | hi-hat 16th + เครื่องเป่าสั้น + shaker | ทีมเรา ≥ 60% **หรือ** คู่แข่ง ≥ 75% | ทั้งสองเงื่อนไขต่ำกว่าเกณฑ์ − 10% |
| L4 ไคลแมกซ์ | `mus_task_L4` | สาย/ซินธ์ไล่ขึ้น + กลองทอม | ทีมใดทีมหนึ่ง ≥ 85% **หรือ** เวลา ≤ 20 วิ | ไม่ปิดจนจบรอบ |

- **เร่งจังหวะ:** เมื่อ L4 เปิด เพิ่ม tempo ทั้งเพลง **+8%** Unity ไม่มีการยืดเวลาแบบคงระดับเสียงในตัว (เปลี่ยน `pitch` จะทำให้เสียงสูงขึ้นด้วย) จึงใช้ **stem ชุด fast ที่ 130 bpm ที่ผลิตมาพร้อมกัน** แล้ว crossfade 1 ห้อง ดูข้อ 4
- **hysteresis:** เกณฑ์ปิดต่ำกว่าเกณฑ์เปิด 10% กันเลเยอร์เปิด-ปิดสลับไปมาเมื่อแถบถอยเพราะคราบลาม
- **คู่แข่งใกล้ชนะ:** เมื่อคู่แข่ง ≥ 85% (แถบคู่แข่งอัปเดตแบบทันทีตอนนี้) เพิ่ม filter สูงผ่านเล็กน้อยใน L1 + stinger ต่ำ `sting_rival_step` เพื่อให้รู้ว่าต้องรีบ ไม่ใช้เสียงที่ทำให้รู้สึกผิด

## 3. Stinger (เสียงสั้นตามคีย์เพลง)

| ไฟล์ | เมื่อ | ยาว | หมายเหตุ |
| --- | --- | --- | --- |
| `sting_task_done` | จบขั้นใดๆ ของทีมเรา | 0.3 วิ | 4 แบบสลับ (โน้ตต่างกันในคอร์ด C) กันซ้ำหู |
| `sting_progress_25` / `_50` / `_75` | ทีมเราผ่านขั้น | 0.8 วิ | ไล่ขึ้นตามขั้น |
| `sting_rival_step` | คู่แข่งผ่านขั้น 25% (และทุกขั้นหลัง 85%) | 0.6 วิ | เสียงต่ำกว่า ไม่ดุ |
| `sting_emergency` | คราบฉุกเฉินโผล่ | 0.7 วิ | คู่ `enemy_spawn` |
| `sting_team_win` | ทีมเราถึง 100% | 2.0 วิ | ตัด loop แล้วเล่น outro |
| `sting_round_end` | คู่แข่งถึง 100% / หมดเวลา | 1.5 วิ | สุภาพ น่ารัก (แพ้ต้องไม่เศร้า ตาม 12_Sound_Manifest) |

stinger เล่นทันที (ไม่รอห้อง) ผ่านกลุ่ม mixer `Stingers` และมีเพดาน: เล่นซ้อนได้ไม่เกิน 2 เสียงพร้อมกัน ถ้าเกิน ตัวเก่าที่เหลือ < 50% ถูกตัด

## 4. การเปลี่ยนเลเยอร์ (quantize)

```
สถานะเกมเปลี่ยน → คำนวณเลเยอร์เป้าหมาย → รอขอบห้องถัดไป (ทุก 2.0 วิ ที่ 120 bpm)
→ fade stem ที่เปิด 0 → 0 dB ใน 1 ห้อง (2 วิ) / stem ที่ปิด 0 → −80 dB ใน 1 ห้อง
```

- ทุก stem เริ่มพร้อมกันด้วย `AudioSource.PlayScheduled(dspStart)` ตัวเดียวกัน แล้วปรับ volume เท่านั้น (ไม่ start/stop กลางเพลง) จึงไม่มีทางหลุดจังหวะ
- เปลี่ยนเป็นชุด fast (130 bpm): เริ่มชุด fast ตั้งแต่ต้นรอบแบบเงียบไม่ได้เพราะความยาว loop ต่างกัน จึง schedule ชุด fast ให้เริ่มที่ขอบห้องถัดไป แล้ว crossfade 1 ห้อง หยุดชุดปกติหลัง fade
- 10 วิสุดท้าย: `timer_tick` ตรงจังหวะเพลง (schedule ที่ beat ถัดไปจาก dspTime)

## 5. Ducking

| สถานการณ์ | ผล |
| --- | --- |
| เปิดมินิเกม (การ์ด S28) | L2–L4 ลด −6 dB ใน 0.3 วิ ให้เสียงขัด/ฉีด/กวาดชัด, L1 คงเดิม |
| เสียงพูด / แชทเสียง | เพลงทั้งหมด −8 dB (side-chain จากกลุ่ม Voice) |
| หยุดเกมออฟไลน์ | low-pass 800 Hz + −10 dB |
| ใบงาน (S20) / ผลรอบ (S26) | ใช้เพลงเมนูสั้นหรือ L1 อย่างเดียว −6 dB |

## 6. ทำใน Unity

- สคริปต์ใหม่ `unity/Assets/Scripts/Audio/BobMusicLayers.cs` (ยังไม่สร้าง)
  - ถือ `AudioSource` 4 ตัว (+4 ตัวสำหรับชุด fast) ใต้ prefab `BobAudio`
  - อินพุต: `OnProgress(teamPct, rivalPct)`, `OnTimeLeft(sec)`, `OnMinigameOpen(bool)`, `OnRoundEnd(won)` จาก `Modular/TaskManager.cs` (อีเวนต์ `ProgressStep`, `TaskCompleted`)
  - คำนวณเลเยอร์เป้าหมายตามข้อ 2 แล้ว quantize ตามข้อ 4 ด้วย `AudioSettings.dspTime`
- `AudioMixer` กลุ่ม: `Music/L1..L4`, `Stingers`, `SFX`, `Voice` · snapshot `Minigame` (ducking) และ `Paused`
- ไม่ใช้ middleware (FMOD/Wwise) ในขั้นนี้ GDD 10 แนะนำ FMOD ไว้ ถ้าย้ายภายหลัง ใช้ parameter `team_pct`, `rival_pct`, `time_left` แทนตรรกะในสคริปต์
- ออฟไลน์/Solo ใช้ตรรกะเดียวกัน คู่แข่งจำลองส่ง `rivalPct` ตามเดิม

## 7. ผลิตไฟล์เพลง

| ทางเลือก | ข้อดี | ข้อเสีย |
| --- | --- | --- |
| **จ้างนักแต่งทำ stem เฉพาะเกม (แนะนำ)** | ได้ stem ที่ตรง bpm/คีย์ และชุด fast ในงานเดียว เป็นของเรา 100% | มีค่าใช้จ่าย ใช้เวลา 1–2 สัปดาห์ |
| ทำเองใน DAW (เช่น LMMS, BandLab ฟรี) | ฟรี คุมได้ทุกอย่าง | ต้องมีคนทำเพลง |
| เพลง AI (ElevenLabs Music ฯลฯ) | เร็ว | เครดิตเดิมหมดแล้ว และส่วนใหญ่ออกมาเป็นเพลงเต็ม ไม่แยก stem ต้องตรวจเงื่อนไขการใช้เชิงพาณิชย์ |
| CC0 loop แยก stem | ฟรี | หายากมากที่จะได้ 4 stem ตรงกัน ใช้เป็น placeholder เท่านั้น |

**placeholder ระหว่างรอ:** ใช้ `music_placeholder_loop` (CC0 เดิม) เป็น L1 และสังเคราะห์ L2–L4 แบบง่ายด้วย `art/tools/make_sfx.py` ฉบับเพิ่มเติม (ยังไม่ทำ) เพื่อทดสอบตรรกะก่อน

ทุกไฟล์ที่ไม่ใช่ของเราเองต้องลงตาราง licence ใน `12_Sound_Manifest.md` ข้อ 4 ก่อน commit

## 8. ทดสอบ

- เปิด/ปิดเลเยอร์ต้องตรงขอบห้อง: บันทึก dspTime ทุกการเปลี่ยน แล้วตรวจว่าเป็นพหุคูณของ 2.0 วิจาก dspStart (เทสต์ PlayMode)
- ไม่มีการเปิด-ปิดซ้ำภายใน 4 วิ (hysteresis) เมื่อจำลองคราบลาม 3 ครั้ง
- ฟังบนลำโพงมือถือ: L1 ต้องยังได้ยินเบสบนลำโพงเล็ก (เน้นย่าน 100–200 Hz ไม่ใช่ sub)
- ถามผู้ทดสอบหลังรอบ: "รู้ไหมว่าคู่แข่งใกล้ชนะตอนไหน" ถ้าตอบได้โดยไม่ได้มองแถบ = ดนตรีทำงาน
