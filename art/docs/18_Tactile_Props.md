# 18 · ผิวสัมผัสของวัตถุในมินิเกม (Tactile Props) แบบไม่ใช้ artist

เวอร์ชัน 1.0 · 13 พ.ย. 2026 · สถานะ: **ตกลงแนวทางแล้ว** · มีต้นแบบเว็บ 2 ชิ้น ยังไม่ได้ลงโค้ด Unity
ใช้คู่กับ `16_Task_Race_Minigame_Spec.md` (มินิเกม), `11_UX_UI_Spec.md` S28 (การ์ด), `00_Art_Direction.md` (สไตล์) และ `03_Unity_Spec.md` ข้อ 5 (shader)

**สรุป:** โปรเจกต์ไม่มี artist แต่ต้องการวัตถุในมินิเกมที่รู้สึกจริงระดับเกมเชิงพาณิชย์ เช่น ฟองน้ำที่เช็ดคราบได้จริงหรือผ้าที่บิดได้จริง โดยไม่หลุด concept จึงแบ่งงานเป็น 3 ทาง:

1. **ความสมจริงจาก shader และโค้ด** ส่วนนี้ไม่ต้องวาดอะไร ได้แก่คราบที่ถูกลบตามรอยนิ้ว รอยเปียกที่ค่อยๆ แห้ง ฟอง ฟองน้ำที่ยุบได้ ผ้าที่บิดเป็นเกลียว และน้ำที่หยด
2. **รูปทรงของ prop จาก AI แบบภาพเป็น 3D** เอาภาพ Leonardo RAW (`10_Leonardo_RAW.md`) ที่ตรง concept อยู่แล้วไปแปลงเป็นโมเดล 3D แล้วใช้สคริปต์ Blender ลดจำนวน polygon และปรับสีให้เข้าพาเลต
3. **ชุด asset ฟรี CC0** สำหรับของประกอบฉาก แล้วเปลี่ยนสีให้ตรงพาเลต

ต้นแบบที่ลองแล้วอยู่ที่ [`ux/BOB_Tactile_Test.html`](ux/BOB_Tactile_Test.html) มี 2 ชิ้นคือฟองน้ำถูคราบ (T02) และบิดผ้าถู (T06) ทำด้วย three.js r128 ใช้นิ้วหรือเมาส์ลองได้ Krits ตกลงแนวทางนี้เมื่อ 13 พ.ย. 2026

## 1. กฎที่ทำให้ไม่หลุด concept

| เรื่อง | กฎ |
| --- | --- |
| รูปทรง | ทรงการ์ตูน ขอบมน สัดส่วนตาม Art Board ไม่ปั้นรายละเอียดแบบของจริง |
| แสงเงา | toon ramp 3 ขั้นแบบนุ่ม เงาอมม่วงหรือฟ้า ไม่ใช่ดำ (`00_Art_Direction.md`) |
| เส้นขอบ | inverted hull สีน้ำตาลเข้ม `#4A2E22` ตาม `00_Art_Direction.md` (ใน `03_Unity_Spec.md` เขียน `#2B2D42` ต้องเลือกค่าเดียว ดูข้อ 7) |
| สี | คราบ ฟอง น้ำ และผ้า ใช้สีจากพาเลต concept เท่านั้น ห้ามใช้ texture ภาพถ่าย |
| ไฮไลต์ | ความวาวของน้ำและคราบมันเป็นจุดสว่างแบบตัดขั้น (step) ไม่ใช่ไล่เฉดแบบ PBR |
| ความสมจริง | มาจากการเคลื่อนไหว การตอบสนองต่อนิ้ว อนุภาค เสียง และการสั่นเท่านั้น |

## 2. เทคนิคหลัก (ใช้ซ้ำได้ทุกมินิเกม)

| เทคนิค | ทำอะไร | ใน Unity | ในต้นแบบเว็บ |
| --- | --- | --- | --- |
| **Paint mask** | คราบหรือฝ้าถูกลบเฉพาะตรงที่นิ้วผ่าน ลบทีละนิด ถูเร็วเหลือรอยเป็นทาง | `RenderTexture` 512×256 ต่อการ์ด + brush material ผ่าน `CommandBuffer`/`Graphics.Blit`; วัด % ที่เหลือด้วย `AsyncGPUReadback` ที่ 64×32 ทุก 0.3 วิ | canvas 2D `destination-out` + `CanvasTexture` |
| **Wet / foam mask** | รอยเปียกและฟองตามรอยถู ค่อยๆ แห้ง ฟองหายเร็วกว่า | RenderTexture 256×128 อีกใบ ลดค่าทุกเฟรม (`_DryRate`) | canvas ที่ลบทีละนิดทุกเฟรม |
| **Squash & stretch** | ฟองน้ำ ไม้ถู และศัตรู ยุบเมื่อกด ยืดตามทิศที่ลาก เอียงตามความเร็ว | สคริปต์ `BobSquash` (spring) ปรับ scale/rotation; ไม่ต้องใช้ rig | scale + lerp ตามความเร็ว |
| **Twist deform** | ผ้าบิดเป็นเกลียวและคอดลง รอยพับกลายเป็นลายเกลียว | vertex shader `_Twist`, `_Squeeze`, `_Height` บน mesh ผ้า (ปลายบนยึด) | `onBeforeCompile` ของ `MeshToonMaterial` |
| **Absorb tint** | ฟองน้ำหรือผ้าซึมสีคราบ หรือเปลี่ยนสีจากเปียกเป็นหมาด | `_TintAmount` ใน material | lerp สี material |
| **Drips & ripples** | น้ำหยดถี่ตามความเร็วที่บิด ตกถังแล้วเป็นวงกระเพื่อม | `ParticleSystem` + sub-emitter ripple | mesh pool |
| **Liquid wobble** | น้ำในขวดหรือถังกระเพื่อมตามการเท | shader ระดับน้ำ + sine wobble ตาม acceleration | ยังไม่ทำ |

ทุกเทคนิคเป็นของ `MinigameHost` ที่ใช้ร่วมกัน (spec 16 ข้อ 9) ไม่ต้องเขียนใหม่ต่อมินิเกม

## 4. รูปทรงจาก AI และชุด CC0

| แหล่ง | ใช้กับ | เงื่อนไข |
| --- | --- | --- |
| TRELLIS (open source, MIT) | prop แข็งรูปทรงง่าย: ขวด ถัง จาน เก้าอี้ แกลลอน | รันเองได้ต้องมี GPU; ใช้ภาพ Leonardo RAW เป็นภาพตั้งต้น |
| Tripo / Meshy (เสียเงิน) | ชิ้นที่ TRELLIS ออกมาไม่ดี | ใช้เชิงพาณิชย์ได้เฉพาะบางแผน **ตรวจเงื่อนไขล่าสุดก่อนใช้** |
| KayKit, Quaternius, Kenney (CC0) | ของประกอบฉากในห้อง | ใช้ได้ทุกกรณี บันทึกที่มาใน `02_Asset_List.md` |

ขั้นตอนหลังได้โมเดล (สคริปต์ Blender ที่รันแบบ headless ได้): ลดเหลือ 150–800 tris ต่อ prop (ใกล้เคียงชิ้นส่วนและอุปกรณ์ใน budget ของ `03_Unity_Spec.md` ข้อ 2) ชิ้นที่ผู้เล่นจับและบิดหรือยุบได้ถึง 1,500 tris, texture รวมใน atlas 1024², วาง pivot ที่ฐาน, map สี texture เข้าพาเลต concept, ใส่ material `BOB/ToonLit` + `BOB/Outline`

ผมประเมินเองว่ารูปทรงจาก AI จะได้คุณภาพราว 70–80% ของงาน artist แต่ในการ์ดมินิเกมไม่สะดุดตา เพราะผู้เล่นเห็นแค่ไม่กี่วินาทีและสายตาจับอยู่ที่ผลจากเทคนิคในข้อ 2

## 5. งบประสิทธิภาพบนมือถือ

| รายการ | งบ |
| --- | --- |
| RenderTexture ต่อการ์ด | สูงสุด 2 ใบ (mask 512×256 + wet 256×128) เปิดได้ทีละการ์ด ปิดการ์ดแล้วคืน |
| อนุภาค | ≤ 80 ต่อการ์ด |
| prop ในการ์ด | ≤ 6 ชิ้น รวม ≤ 8,000 tris |
| เวลา GPU ของการ์ด | ≤ 4 ms บนเครื่องระดับกลาง (ตั้งเป้า ยังไม่ได้วัด) |

## 6. ลำดับงานต่อไป

1. ย้ายต้นแบบ T02 และ T06 ลง Unity: `BOB/PaintMask` (brush + วัด %), `BOB/ClothTwist`, `BobSquash`, ระบบหยดน้ำ แล้ววัดบนมือถือจริง
2. ทำเทคนิคที่เหลือตามลำดับ MVP ใน spec 16: T01 → T03 → T05 → T09 → T13 → T16
3. ลองแปลงภาพ Leonardo เป็น 3D 3 ชิ้นแรก (ฟองน้ำ ขวดสเปรย์ ถังน้ำ) เพื่อเทียบคุณภาพกับ sprite เดิม
4. เสียงที่ผูกกับเทคนิค (`scrub_loop`, `wring`, `water_pour`) ใช้ตาม `12_Sound_Manifest.md` ข้อ 6

## 7. คำถามที่ยังเปิด

- สีเส้นขอบ: `00_Art_Direction.md` ใช้ `#4A2E22` แต่ `03_Unity_Spec.md` ใช้ `#2B2D42` ต้นแบบนี้ใช้ `#4A2E22` ตาม Art Direction ต้องเลือกค่าเดียวแล้วแก้อีกไฟล์ให้ตรงกัน
- มินิเกมจะเป็น prop 3D ในการ์ด หรือเป็น sprite 2D + shader ตาม F27/F28 เดิม ต้นแบบนี้ใช้ 3D และผมแนะนำให้ใช้ 3D สำหรับวัตถุที่ผู้เล่นจับ (ฟองน้ำ ผ้า ไม้ถู ขวด) ส่วนฉากหลังของการ์ดยังเป็น 2D ได้
