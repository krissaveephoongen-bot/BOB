## 2. ลีดเดอร์บอร์ด (ทำแล้ว 17 พ.ย. 2026)

คะแนนของแมตช์เดียว สูตรเดียวอยู่สามที่และถูกล็อกด้วยตารางเลขชุดเดียวกัน
(`BobRaceScore.Of` ฝั่งเครื่อง · `taskRaceScore` ใน `prototype/index.html` · `server/modules/index.js`):

```
raw = งานที่ทำ * 100 + เงื่อนไขรถเข็นที่ผ่าน * 75 + วินาทีที่เหลือ * 2 + (ชนะ 400 / เสมอ 150)
คะแนน = raw * (100 + 20 * (D - 1)) / 100        D1 = 1.00, D2 = 1.20, D3 = 1.40 (หารปัดลง)
```

- เพดานกันโกงเลขเฟ้อ: งานไม่เกิน 99, เงื่อนไขรถเข็นไม่เกิน 4, วินาทีที่เหลือไม่เกิน 120
- บทที่จบทั้งบทใช้ **ยอดรวมของซีรีส์** ไม่ใช่รอบสุดท้ายรอบเดียว; ช่องรถเข็นของบทนับ "ครั้งที่ล็อกผ่าน" (0–3)
  ส่วนรอบเดี่ยวนับ "เงื่อนไขที่ผ่าน" (0–4)
- การส่ง: `TaskRaceModeManager.EndMatch` ตั้ง `LastScore` → `BobRaceScoreReporter` ฟัง `MatchEnded` แล้วส่งเข้า
  `global_high_score` ครั้งเดียวต่อแมตช์ เฉพาะเมื่อ `LastMatchRecorded` และเครื่องล็อกอินแล้ว
- **รอบซ้อมไม่ขึ้นบอร์ด (26 พ.ย. 2026, docs 11 S41):** ค่าที่จูนจากแผง `ปรับแต่ง (ซ้อม)` ทำให้ `EndMatch` ปิด `record`
  ⇒ `LastMatchRecorded = false` ⇒ `BobRaceScoreReporter` ไม่ส่ง และไม่จ่ายเหรียญ/XP/ดาวด้วย; ออนไลน์อ่านค่าของบทเสมอ
- หน้าผล (S27) แสดง `คะแนน N · สถิติ ...` ในบล็อกรางวัล — เห็นทันทีว่าเลขที่ขึ้นบอร์ดคือเท่าไร (รอบซ้อมขึ้นชิป
  `รอบซ้อม · ไม่ส่งอันดับ ไม่บันทึกดาว` แทน)

**ด่านที่คุมสูตรนี้:** `unity-check` (C# 10 แถว) + `server/task-race-test.js` (JS 10 แถวเดียวกัน + กฎเพดาน)
⇒ `UNITY-CHECK PASSED`, 80/80

**ข้อจำกัดที่ต้องรู้:** UGS รับคะแนนที่ client ส่ง ไม่ตรวจย้อนหลัง (ดู docs 27 §7) — กันโกงจริงต้องย้ายการคิดคะแนน

## 2.2 เดลี่ (seed จากเซิร์ฟเวอร์ · ทำแล้ว 17 พ.ย. 2026)

เจ้าของตอบข้อ 3 ว่า **"server เป็นคนออก seed"** จึงไม่มี `Date.now()` เป็น seed ที่ไหนเลยในเส้นทางนี้

- **ปลายทาง:** `GET /daily/seed` ตอบ `{ok, day, dayNumber, seed, rounds, nextDayInSec}` — ตัวเดียวกันทั้ง HTTP และ
  RPC `bob_daily` (Nakama) เพราะเรียกฟังก์ชันชุดเดียวกันใน `server/daily.js`
- **รันเองได้:** `node server/daily-server.js` (พอร์ต 8099) — ไม่มีฐานข้อมูล ไม่รู้จักผู้เล่น เพราะ seed เท่ากันทุกคน
- **วันเปลี่ยนตอนเที่ยงคืนเวลาไทย (UTC+7)** ไม่ใช่ UTC: `dayNumber = floor((ms + 7h) / 24h)` ⇒ 2026-11-17 = 20774
- **seed = 1 + floor(mulberry32(dayNumber ^ 0x02f6e2b1) * 8388607)** — ฟังก์ชันของ "วัน" ล้วน ๆ ไม่ขึ้นกับเวลาในวัน
- **เครื่องตรวจคำตอบเอง:** `BobDaily.Matches(seed, dayNumber)` ต้องจริงก่อนเริ่มแมตช์ คำตอบที่ถูกตัด/แก้/ค้างวันจะถูกปฏิเสธ
  และการ์ดจะบอกว่าใช้ไม่ได้ แทนที่จะเริ่มชุดงานที่ไม่มีใครเล่นเหมือนกัน
- **1 รอบต่อวัน ต่อเครื่อง:** ตัวเซิร์ฟเวอร์ไม่รู้ว่าใครถาม จึงนับที่เครื่อง (`PlayerPrefs bob.daily.day/plays`)
  คีย์ด้วย "วันที่เซิร์ฟเวอร์บอก" ไม่ใช่วันของมือถือ ⇒ เปลี่ยนนาฬิกาเครื่องก็ไม่ได้รอบเพิ่ม
- **ต่อบัญชี (17 พ.ย. 2026):** โปรไฟล์คลาวด์พก `dailyDay`/`dailyPlays`; `BobDaily.PlaysToday` ใช้ **ค่าที่มากกว่า**
  ระหว่างเครื่องกับคลาวด์ของ "วันเดียวกัน" ⇒ ลงเครื่องใหม่ไม่รีเซ็ตรอบที่บัญชีใช้ไปแล้ว และเครื่องที่เล่นออฟไลน์ก็ไม่ถูกลงโทษ;
  `BobDailyStore.AdoptCloud` เรียกตอนโหลดโปรไฟล์ และ `Consume` เขียนกลับทันที (`SetDailyAndSaveAsync`)
- **บอร์ดเดลี่แยกวัน (17 พ.ย. 2026):** รอบเดลี่ลงบอร์ด `daily_<dayNumber>` (`BobDaily.DailyBoardName`) **เพิ่มจาก**
  บอร์ดรวม `global_high_score` เฉพาะเมื่อ `MatchRequest.Daily` — บอร์ดที่ยังไม่สร้างใน dashboard แค่ล็อก warning
  ไม่ทำให้การลงบอร์ดรวมล้ม (`BobDaily.ValidBoardName` กันชื่อผิดรูปก่อนเรียก API)
- **การ์ดในเกม:** Home → dock `เดลี่` แสดง `วัน 2026-11-17` · `เหลือ 1 รอบวันนี้` (หรือ `เล่นแล้ววันนี้ · กลับมาพรุ่งนี้`) ·
  `seed N · ทุกคนได้ชุดงานเดียวกัน` · ปุ่ม `เล่นเดลี่` (กดแล้ว `MatchRequest.SetDaily` → ฉาก TaskRace รอบเดียว)
- **อันดับเดลี่บนการ์ด (17 พ.ย. 2026):** ใต้ปุ่มเล่นมีการ์ดอ่าน top 5 ของ `daily_<day>` วันนั้น (`BobBoardService.LoadDailyAsync`
  → `GetDailyScoresAsync`, แถวเดียวกับหน้าอันดับรวม) — โหลดในพื้นหลัง, การ์ดขึ้น `กำลังโหลดอันดับ…` ก่อน,
  ออฟไลน์ขึ้น `ออฟไลน์ · ยังดูอันดับวันนี้ไม่ได้`, ยังไม่มีคะแนนขึ้น `วันนี้ยังไม่มีใครส่งคะแนน`; **ไม่ทำเครื่องหมายแถวตัวเอง**
  เพราะอันดับในหน้าเดลี่ของเครื่องนี้ยังไม่ได้อ่าน และการเดาจะทำให้การ์ดโกหก
- **ใช้ attempt ตอนจบแมตช์** (`TaskRaceModeManager.EndMatch`) ไม่ใช่ตอนเปิดการ์ด ⇒ แมตช์ที่ยังไม่เริ่มไม่กินรอบ
- **ค่าเริ่มต้นของ URL** คือ `http://127.0.0.1:8099/daily/seed` (เดสก์ท็อป/อีมูเลเตอร์เครื่องเดียวกัน) — เครื่องจริงต้องตั้ง
  `bob.daily.url` เป็นที่อยู่ที่ deploy แล้ว; ถ้าเรียกไม่ถึง การ์ดขึ้น `ออฟไลน์ · เล่นโหมดปกติไปก่อน` และโหมดอื่นเล่นได้ปกติ

**ด่านที่คุมส่วนนี้:** `node server/daily-test.js` = **34/34** ประกอบด้วย (ก) กฎ: ตาราง seed 6 แถว, เขตเที่ยงคืน UTC+7,
`dailyInfo` ที่ปักนาฬิกาได้, การเทียบสำเนาใน `prototype/index.html` ทีละค่า (ข) **HTTP จริง**: เปิดเซิร์ฟเวอร์บนพอร์ตชั่วคราว
แล้วยิงคำขอจริง 200 / 409 `stale_day` / 404 / 405 และตรวจว่าไม่แคช (`no-store`) — `unity-check` พิมพ์ตัวเลขชุดเดียวกัน
จาก `BobDaily.cs` (`daily seed table checked`) ⇒ ถ้าฝั่งใดเพี้ยน ด่านใดด่านหนึ่งแตก

**ยังไม่ได้ทำในส่วนนี้:** ยังไม่มีการกันโกงฝั่งเซิร์ฟเวอร์ · ยังไม่มีการยืนยันว่าผู้เล่นคนเดียวกันเล่นได้วันละรอบจากหลายเครื่อง
ด้วย token ของ UGS โดยตรง (ตอนนี้ใช้ค่ามากสุดที่ซิงก์ขึ้นคลาวด์) · ยังไม่มีหลักฐานบอร์ดเดลี่จริงบนคลาวด์ (sandbox ไม่มี UGS)
· การ์ดยังไม่ไฮไลต์อันดับของเครื่องตัวเอง (ต้องอ่าน `GetPlayerScoreAsync` ของบอร์ดวันนั้นก่อน)

- **ตัดเย็บ 4 ชั้น (P1 · 17 พ.ย. 2026):** แท็บที่สาม `ตัดเย็บ` ของตู้เสื้อผ้าใช้ `Rules/BobSewing.cs` —
  ผ้า 4 / สี 4 / ลาย 4 / เครื่องประดับ 4 (ตัวเลือกละชิป, ราคาโชว์บนชิป). ราคา = 30 เหรียญ + ชั้นที่เลือก (รวม 40–66)
  และ 1–2 เกล็ด; เกล็ดได้จากแมตช์ (`ShardsEarned` = 1 + ทุก 3 แมตช์) และใช้แล้วหมด (`bob.sew.shards`) ปุ่ม `ตัดชุดนี้`
  ตรวจทั้งสองราคาก่อนหัก แล้วจึง `BobTaskRaceProfile.Spend` + `BobCosmetics.SpendSewShards` + `WearSewn`
- **ผ้าที่ตัดเองอ่านได้เสมอ:** สีผ้า = สีผ้าเดิม ผสมสีที่เลือก 45% แล้วยกขึ้นทางครีมทีละ 10% จนผ่าน `BobCartPaint.Readable`
  ⇒ ครบทั้ง 4×4 คู่ (ด่าน `sewing table checked`); ชุดที่ใส่ทับสีกรอบบนจานรอง, แถบ XP และตัวรถเข็น T04 และไม่ถูกกติกาใดอ่าน
- **ชุดตัดเย็บข้ามเครื่อง:** `sewnLook` ("1:2:0:3") เดินทางในโปรไฟล์คลาวด์; `AdoptCloud` รับชุดจากคลาวด์เมื่อเครื่องยังไม่มี
  และถอดรหัสได้เท่านั้น; `ถอดทั้งหมด` ล้างป้าย กรอบ และชุดพร้อมกัน
- **กระเป๋า (S33 · 17 พ.ย. 2026):** แท็บที่สี่ `กระเป๋า` เป็นครึ่งอ่าน-อย่างเดียวของตู้เสื้อผ้า: `Rules/BobBag.cs`
  นับของที่ถือแยกป้าย/กรอบจากตารางเดิม (id แปลกและ id ซ้ำไม่ถูกนับ), พิมพ์ `ของแต่ง n ชิ้น · ป้าย a · กรอบ b`,
  บรรทัดเกล็ด `เหลือ l · ได้มา e · ใช้ไป e-l` (left ถูกบีบไม่ให้เกิน earned ⇒ ไม่มี "ใช้ไป" ติดลบ) และบรรทัด
  `ขายคืนไม่ได้ · ของแต่งไม่เพิ่มพลัง`; ตัวการ์ดวาดชุดตัดเย็บที่ใส่ (ถ้ามี) + ของทุกชิ้นที่ถือเป็นการ์ดสี/ชื่อ/ที่โผล่
  **ไม่มีปุ่มซื้อ ขาย หรือใช้ในแท็บนี้** — ของที่ใช้ได้ยังใช้จากสองแท็บแรก
- **ยังไม่ทำ:** ของที่ต้องใช้เพชร/ event · เศษวัสดุหลายชนิด (ตอนนี้มีเกล็ดตัดเย็บชนิดเดียว) ·
  การกันโกงฝั่งคลาวด์ (ตอนนี้เครื่องเป็นคนตัดสิน ซึ่งยอมรับได้เพราะของไม่มีผลกับกติกา) · ตัวละคร 3D ที่ใส่ชุดจริง (sandbox ไม่มี Unity)

**ด่านที่คุมส่วนนี้:** `unity-check` — `unlock table checked` (13 ข้อ: ความใหม่ของผู้เล่น, เงื่อนไขแต่ละชิ้นทั้งผ่าน/ไม่ผ่าน,
เพดานความคืบหน้า, ข้อความ `วันเดลี่ 1/3`, `Missing` คืนเฉพาะที่ถึงและยังไม่มี, กรอบมีสี/ป้ายไม่มีสี) และ
`cart paint checked` (6 ข้อ: รถเปล่า = ครีมเดิม, ครีมอ่านได้, สีกรอบทุกสีมองเห็น, ตัวรถยังสว่างพอ, น้ำหนักเป็นแค่การแต้ม,
ตัวอ่าน hex รับ/ปฏิเสธถูก) และ `wardrobe checked` (10 ข้อ: สองแท็บแบ่งครบ 6 ชิ้น, ทุกชิ้นบอกที่โผล่, รวมรายการคลาวด์
ไม่ซ้ำ/ไม่ทิ้งของเครื่อง, ไม่ใส่ของที่ไม่ได้ถือ, ไม่ข้ามช่อง, id เก่าตกไปใช้ของคลาวด์) และ `sewing table checked`
(9 ข้อ: 4 ชั้นละ 4 ตัวเลือก, ทุกคู่ผ้า×สีอ่านได้, การยกสี, ปฏิเสธชุดไม่ครบ, ราคา 40–66, encode/decode, คำอธิบาย, เกล็ด)
และ `bag checked` (6 ข้อ: กระเป๋าว่าง, แยกป้าย/กรอบโดยไม่นับ id ซ้ำ/แปลก, หัวบรรทัดมีครบสามตัวเลข, จำนวนติดลบถูกบีบ,
บรรทัดเกล็ดไม่พิมพ์ค่าติดลบ, บรรทัดขายคืน)

## 2.4 ออนไลน์ชนะ 2 ใน 3 (ทำแล้ว 17 พ.ย. 2026)

เจ้าของตอบข้อ 5 ว่าใช้ **UGS Relay/Lobby** ต่อจากห้องเดิม ไม่กลับไป Nakama. รอบนี้จึงไม่ได้เพิ่มบริการใหม่
แต่ทำให้ห้องออนไลน์ใช้กติกาซีรีส์ชุดเดียวกับออฟไลน์ (`StorySeries`) — สรุปสัญญา (รายละเอียดใน docs 27 §10.7):

- **สถานะซีรีส์อยู่ในห้อง:** `BobOnlineRoom.Series` (รอบละ 100 วิ, ชนะ 2) ทุกเครื่องอ่านตัวเดียวกันผ่าน
  `TaskRaceModeManager.series`; จำนวนรอบไม่ขึ้นกับว่าเครื่องไหนจบงานก่อน
- **host ตัดสินรอบเดียว:** host `Register` แล้วส่ง `bob.result` (ผล + งาน + แต้มของทั้งสองฝ่าย); client
  `RegisterOutcome` ตามผลนั้นและ **hold** ที่ท้ายรอบ (`รอบจบ · รอเจ้าของห้องสรุปผล`) แทนการปิดแมตช์เอง
- **client เห็นไม่ตรง (17 พ.ย. 2026):** ก่อนรับผลของ host client เทียบงานของตัวเองกับบรรทัดที่ host ส่ง
  (`Rules/BobSeriesCheck.Agrees`: งานตรงเป๊ะ, แต้มต่างได้ ≤10%); ไม่ตรง → `series.NoteDisputed()` ครั้งเดียว
  แล้วการ์ดออนไลน์ขึ้นบรรทัด `ผลไม่ตรงกับที่เห็น n รอบ · เจ้าของห้องตัดสิน` — **ผลของ host ยังชนะเสมอ** ไม่มีการโต้แย้งในเกม
- **seed รอบ 2–3:** host ออกและส่ง `bob.round(round, seed, seconds)` — client ไม่ reroll จึงได้ใบงานชุดเดียวกัน
- **ออกกลางซีรีส์:** `StorySeries.Abandon()` → ซีรีส์เป็นโมฆะ ไม่มีผู้ชนะ (host broadcast `bob.abandon`
  หรือ client เห็นห้องหลุดเอง); ซีรีส์ที่ตัดสินแล้วไม่ถูกยกเลิก
- **การ์ดผล:** `ชนะซีรีส์!` / `แพ้ซีรีส์` / `เสมอซีรีส์` / `ยกเลิกซีรีส์` + `ชนะ w – l` + รอบล่าสุด + รางวัล;
  host ได้ปุ่ม `เริ่มซีรีส์ใหม่`, client รอเจ้าของห้อง
- **บัญชี/รางวัล:** จ่ายรางวัล **ครั้งเดียวตอนจบซีรีส์**; ออนไลน์ไม่เขียนดาวบท/สถิติเนื้อเรื่อง/โบนัสผ่านบทแรก
  (ทุกจุดกันด้วย `!Online`) — บันไดเนื้อเรื่องจึงไม่ถูกปนด้วยผลห้องออนไลน์
- **ยังไม่มี:** server validation ของผลรอบ, reconnect/host migration/late join, สองทีมจริง

**ด่านที่คุมส่วนนี้:** `unity-check` +11 ข้อ (ผลรอบ/โมฆะ/ผู้ชนะ/บรรทัดเก่า/`Reset`) พร้อม `UNITY-CHECK PASSED`;
ยังไม่มีหลักฐานสองเครื่องจริง (sandbox ไม่มี Unity/UGS)
