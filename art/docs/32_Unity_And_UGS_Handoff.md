| A5 | `TaskRaceVerify.Run / RunDuo / RunTeam` (ข้อ 12) | `done` ทั้งสาม (solo 0/9, duo/team 0/13) | edit-modeล้วน batchmode ได้ |

จากนั้น **ตรวจด้วยตา 6 อย่างที่ sandbox ไม่เคยเห็น** (ยังไม่มีภาพใน Unity เลยสักรอบ):

1. **ตู้เสื้อผ้า → แท็บ `กระเป๋า`**: หัวบรรทัด `ของแต่ง n ชิ้น · ป้าย a · กรอบ b` (หรือ `ยังไม่มีของแต่ง · เล่นแมตช์เพื่อปลด`),
   บรรทัด `เกล็ดตัดเย็บ · เหลือ l · ได้มา e · ใช้ไป e-l`, การ์ดของที่ถือ (สี/ชื่อ/ที่โผล่) เรียงแถวละ 3,
   บรรทัดปิด `ขายคืนไม่ได้ · ของแต่งไม่เพิ่มพลัง` และ **ต้องไม่มีปุ่มซื้อ/ขาย/ใช้ในแท็บนี้**
2. **แท็บ `ตัดเย็บ`**: 4 ชั้น × 4 ชิป, ราคา 40–66 เหรียญ + 1–2 เกล็ด, `ตัดชุดนี้` หักทั้งสองราคา, ผ้าที่ได้ยังอ่านออก
3. **การ์ด `เดลี่`**: ใต้ปุ่มเล่นมีบรรทัด `อันดับเดลี่วันนี้ · seed เดียวกันทุกคน` → `กำลังโหลดอันดับ…` → top 5
   (หรือ `วันนี้ยังไม่มีใครส่งคะแนน` / `ออฟไลน์ · ยังดูอันดับวันนี้ไม่ได้`)
4. **การ์ดผลรอบ**: แถบ proof `ห้องสะอาด · เรา x%→y% · คู่แข่ง …` ขึ้นในช่องว่างเหนือการ์ด แตะหรือ 4 วิแล้วหาย
5. **สีรถเข็น T04**: ใส่กรอบสี → ตัวรถครีมผสมสีกรอบ 28% + ริบบางสีเต็มด้านล่าง; ไม่ใส่ = ครีมเดิมเป๊ะ
6. **ตู้เสื้อผ้าเปิดใหม่**: draft ของโต๊ะตัดเย็บเริ่มจากชุดที่ใส่อยู่ (ไม่ใช่ช่อง 0 ทั้งสี่)

## 3. คิว B — UGS dashboard: สร้างของให้ครบตามที่โค้ดเรียก

โค้ดเรียกชื่อเหล่านี้ตายตัว — ถ้าไม่มีของใน dashboard จะได้แค่ warning ไม่ crash แต่จะไม่มีข้อมูลจริง:

| ของใน dashboard | ชื่อ / ค่า | อ้างอิง |
| --- | --- | --- |
| Leaderboard หลัก | `global_high_score` · เรียงมาก→น้อย · Keep best | `UgsLeaderboardManager.leaderboardId` |
| Leaderboard เดลี่ | `daily_<dayNumber>` เช่น **`daily_20774`** (17 พ.ย. 2026) · ตั้งค่าเดียวกับหลัก | `BobDaily.DailyBoardName` |
| Cloud Save | entry key **`player_profile`** เก็บ JSON ของ `PlayerProfileData` | `UgsCloudSaveManager.ProfileKey` |
| ฟิลด์ในโปรไฟล์ | `coins`, `level`, `unlockedItems`, `equippedTitle`, `equippedFrame`, `sewnLook`, `dailyDay`, `dailyPlays` | `UGS/PlayerProfileData.cs` |
| Auth | Anonymous sign-in เปิด | `UgsBootstrapManager` |
| Relay / Lobby | เปิดทั้งคู่, Lobby SDK 1.3.0 | `UGS/BobOnlineRoom.cs` |

**เรื่อง dayNumber:** `dayNumber = floor((epochMs + 7h) / 24h)` (เที่ยงคืนเวลาไทย) — 17 พ.ย. 2026 = `20774`,
18 พ.ย. = `20775`. ต้องสร้างบอร์ดของวันที่จะทดสอบก่อน (โค้ดไม่สร้างบอร์ดเอง; ชื่อผิดรูปจะถูกปฏิเสธที่ `BobDaily.ValidBoardName`).
**พิมพ์รายการบอร์ดที่จะต้องสร้าง (ไม่ต้องคำนวณเอง):**

```bash
node server/daily-boards.js        # วันนี้ + 6 วันข้างหน้า (UTC+7): day · board id · seed · วันที่
node server/daily-boards.js 14     # 14 วัน
node server/daily-boards.js --self-test   # DAILY BOARDS PASSED (9 checks)
```

สคริปต์นี้ใช้ `dailyDayNumber`/`dailyDayLabel`/`dailySeed` จาก `server/daily.js` ตัวเดียวกับ endpoint และเทสต์
⇒ ไม่มีนาฬิกาที่สอง; ส่วนกฎชื่อ `daily_<n>` ยังตรึงด้วย `unity-check` (`daily board checked`) เหมือนเดิม. ตัวสคริปต์ไม่แตะ UGS (สร้างบอร์ดต้องใช้สิทธิ์ dashboard)

> **การตัดสินใจที่ต้องถามเจ้าของ:** จะสร้าง `daily_<day>` ล่วงหน้าทุกวันด้วยมือ หรือจะให้มีสคริปต์/endpoint สร้างให้อัตโนมัติ

## 5. คิว D — ออนไลน์สองเครื่อง (ต้องมี 2 เครื่อง + UGS จริง)

ห้องออนไลน์ 2–4 คนเป็น host-authoritative: host ส่ง `bob.start` (seed) / `bob.round` (seed รอบ 2–3) / `bob.result` (ผลรอบ)
/ `bob.emergency` (คราบ) — client รับและรอ. ทดสอบ 6 สถานการณ์:

1. host สร้างห้อง → เลข 6 ตัวขึ้นใหญ่ → client พิมพ์รหัสเข้าห้องได้ → เห็นกันและกันเดิน
2. เริ่มแมตช์: ทั้งสองเครื่องได้ใบงาน **ชุดเดียวกัน** (เทียบเลข seed ใน Console)
3. จบรอบ 1: client ขึ้น `รอบจบ · รอเจ้าของห้องสรุปผล` ไม่ปิดแมตช์เอง; host ส่งผล → การ์ดทั้งห้องตรงกัน
4. คราบ T16: host วางคราบ → client เห็นคราบเดียวกัน; client ปราบคราบ → host เห็น `เพื่อนปราบคราบแล้ว!` (สลับกันด้วย)
5. ครบ 2 ชนะ: การ์ด `ชนะซีรีส์!` / `แพ้ซีรีส์` ตรงกัน; client ไม่มีปุ่ม `เริ่มซีรีส์ใหม่`
6. client ออกกลางซีรีส์ → host ขึ้น `ยกเลิกซีรีส์` และไม่มีผู้ชนะ; ถ้าซีรีส์ตัดสินแล้ว ออกทีหลังต้องไม่ลบผล

**ยังไม่มีในโค้ด (อย่ารายงานว่าทำได้):** server validation ของผลรอบ, reconnect / host migration / late join, PvP สองทีมจริง
